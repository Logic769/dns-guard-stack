# 历史压测记录（2026-10-17）

> **时效说明**：本记录测于 2026-10-22 之前的旧架构（`nginx -> AdGuard Home -> guard`，单机约 1.8 GiB 内存）。此后系统入口已先后演进为 `dnsdist` 入口（10-22）和 `AdGuard Home` 入口 + 内网 `dnsdist` 缓存（10-28）。以下数据**仅作历史调优参考**，不代表当前架构的性能指标。

---

## 1. 测试口径定义

* **瞬时并发**：单轮突发请求下，100% 成功且 `p99 ≤ 500 ms` 的最大并发数。
* **持续并发（90s）**：持续压测 90 秒，成功率 `≥ 99.9%` 且 `p99 ≤ 500 ms`。
* **持续 QPS**：固定速率发送请求，实际吞吐达标且 `p99 ≤ 500 ms`。

---

## 2. Nginx 调优前后对比（2026-10-17）

### 调优动作

* 将 Nginx DoH `limit_req_zone` 从 `50r/s (burst=100)` 提升至 `200r/s (burst=200)`。
* DoH 上游改为直连 `adgh:443`，开启 `keepalive 128` 与 SSL 会话复用；`limit_conn perip 32` 保持不变。

### 对比结果

| 测试场景 | 调优前表现 | 调优后表现 |
| :--- | :--- | :--- |
| DoH 瞬时并发 | 32 并发触顶（48 并发出现 HTTP 503） | 48 / 64 / 96 / 128 并发全通过（调度 `p99` 8.3–25.2 ms） |
| DoT 瞬时并发 | 64 通过，96 失败 | 128 通过（`p99` 10.0–10.4 ms），192 失败（190/192，2 个 `SERVFAIL`） |
| DoT 持续并发 (90s) | 16 并发 `p99` 达 575.6 ms | 32 并发达 722 qps（`p99` 388.8 ms）；48 并发 `p99` 升至 613.9 ms 破线 |
| DoH 持续并发 (90s) | — | 16 并发 100% 成功（239 qps，`p99` 194.2 ms），吞吐饱和在 260–285 q/s |
| DoH 持续 QPS | 150 r/s 时 `p99` 332.7 ms | 150 r/s 时 `p99` 降至 116.3 ms（-65%），上限约 190 q/s |
| DoT 持续 QPS | — | 400 r/s 在线内（`p99` 449.3 ms），600 r/s 破线（`p99` 581.3 ms） |

调优后执行回归验证：`dnssec-failed.org` 仍返回 `SERVFAIL`，随机未注册标签返回 `NXDOMAIN`，公网 53 端口保持关闭，安全边界未受影响。

## 3. `verifier` 侧车保活优化（2026-10-18）

### 问题定位

压测中发现 `verifier` 执行一致性核对（`corrob` 池）平均耗时高达 447–448 ms。排查发现 DoT 对端在连接空闲 1.5–2 秒后会主动回收连接，而 `verifier.py` 缺少保活线程，导致频繁触发 TLS 冷握手（818–1137 ms vs 热连接 204–226 ms）并出现 `CLOSE-WAIT` 阻塞。

### 优化与结果

在 `verifier.py` 中注入 `guard.prewarm` 与 `guard.keepalive` 线程，新增每 0.5 秒的并发短保活（`GUARD_KEEPALIVE_S=1`）并同步更新 `RELEASE.sha256`：

* `corrob` 池实测均值由 448 ms 降至 **238 ms**（12/12 无冷启动）。
* `verifier` 累计平均耗时由 448.22 ms 降至 **307–327 ms**。
* 间隔 5 秒连续请求的冷启动次数由 6/8 降至 **0/20**。
* 静默 30 秒后的首查耗时由约 1000 ms 降至 **215 ms**。

受限于本机到境外认证通道的物理 RTT（204–226 ms）及进程间通信开销，该通道延迟的物理下限约在 200 ms 左右。

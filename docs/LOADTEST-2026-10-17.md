# 压测报告：DNS 解析链容量与调优（2026-10-17）

对象：本仓库部署的单机解析链（nginx → AdGuard Home → guard 校验链），主机约 1.8 GiB 内存。
目的：给出**瞬时并发 / 持续并发 / 持续 QPS**三项容量口径，并用同一口径验证入口调优前后差异。
说明：本文只保留结论与复现口径；具体服务器地址、域名、证书路径不在公开仓库记录。

## 1. 口径定义

| 口径 | 定义 | 主判据 |
|---|---|---|
| 瞬时并发（burst） | 一次性拉起 N 条连接、每条 1 次查询，看是否全部按时返回 | 成功率 100%，p99 ≤ 500 ms |
| 持续并发（sustained） | 保持 N 条并发长连接循环查询，持续 90 s | 成功率 ≥ 99.9%，p99 ≤ 500 ms |
| 持续 QPS（rate） | 固定目标速率发压，看实际吞吐与尾延迟 | 实际速率达目标，p99 ≤ 500 ms |

语义失败（NOERROR 但缺期望记录、CNAME 抖动）与链路失败（超时/SERVFAIL/503）分开统计。

## 2. 调优前的基线（限流按生产值生效）

| 项 | 结果 |
|---|---|
| DoH 瞬时 | 32 并发通过；48 并发起出现 HTTP 503（limit_conn perip 32 硬墙） |
| DoT 瞬时 | 64 并发通过；96 并发失败 |
| DoT 持续 16 并发 | p99 575.6 ms，已破 500 ms 线 |
| DoH 持续 QPS | 约 180 q/s 天花板 |

## 3. 调优内容（2026-10-17）

1. DoH 入口限速：limit_req_zone rate=50r/s → **200 r/s**；burst=100 → **200**。
2. DoH 上游：proxy_pass https://127.0.0.1:4443（经 docker-proxy）→ **直连 adgh:443** 的 upstream agh_doh，
   keepalive 128、keepalive_timeout 60s，并开启 proxy_ssl_session_reuse on 与 proxy_next_upstream error timeout。
3. limit_conn perip 32 **未改动**（仍是瞬时并发的硬墙）。

生效性验证：nginx -T 中 rate=200r/s、upstream 与 keepalive 均在生效配置；两个 DoH 端口（443/444）都指向 agh_doh；
压测期间 ss 采样连接数峰值 44（keepalive 池生效），docker-proxy 侧为 0。

## 4. 调优后结果

### 4.1 DoH 瞬时并发（limit_conn perip 32 仍是墙）

| 并发 | 结果 | dispatch p99 |
|---|---|---|
| 48 / 64 / 96 / 128 | 全部通过（不再出现 503） | 8.3–25.2 ms |
| 32（限流生效时） | 通过 | 202.6 ms |

### 4.2 DoT 瞬时并发

| 并发 | 结果 | dispatch p99 |
|---|---|---|
| 128 | 通过（2/2） | 10.0–10.4 ms |
| 192 | 失败（2/2）：correct 190/192 = 98.96%，2 条 SERVFAIL，无超时 | 15.2–17.6 ms |

结论：DoT 瞬时墙在 129–192 之间，失败形态是少量 SERVFAIL（上游语义层），不是连接拒绝。

### 4.3 持续并发（90 s）

| 协议 | 并发 | 成功率 | p99 | 实际 qps |
|---|---|---|---|---|
| DoT | 16 | 0.9963 | 444.5 ms | 427 |
| DoT | 24 | 0.9919 | 309.8 ms | 673 |
| DoT | 32 | 0.9888 | 388.8 ms | 722 |
| DoT | 48 | 0.9920 | **613.9 ms** | 852 |
| DoH | 16 | 1.0000 | 194.2 ms | 239 |
| DoH | 32 | 0.9919 | 293.7 ms | 272 |
| DoH | 48 | 0.9868 | 378.3 ms | 260 |
| DoH | 64 | 0.9930 | 493.4 ms | 284 |

链路层无超时/拒绝；未达 99.9% 的档位主要由语义失败与上游 SERVFAIL 构成（按口径计为失败）。
DoT 在 48 并发时 p99 破 500 ms；DoH 吞吐饱和在约 260–285 q/s，16 并发是唯一全绿档。

### 4.4 持续 QPS

| 协议 | 目标 | 成功率 | p99 | 实际 qps |
|---|---|---|---|---|
| DoH | 150 | 1.0000 | **116.3 ms**（调优前同档 332.7 ms） | 150 |
| DoH | 190 | 0.9887 | 232.8 ms | 188 |
| DoT | 400 | 0.9919 | 449.3 ms | 397 |
| DoT | 600 | 0.9941 | **581.3 ms** | 596 |
| DoT | 800 | 0.9988 | **1072.1 ms** | 799 |

调优把 DoH 150 r/s 档的 p99 从 332.7 ms 压到 116.3 ms（−65%）；DoH 天花板约 190 q/s 量级，
继续加档会触发入口 503（准入）而非链路失败。DoT 无入口限速，400 r/s 时 p99 仍在线内，600 r/s 起破线。

## 5. 防投毒边界回归（调优后同一时间窗口）

| 检查 | 结果 |
|---|---|
| 签名域 cloudflare.com（DoT/DoH） | NOERROR，AD=1 |
| dnssec-failed.org（DoT/DoH） | SERVFAIL（不降级放行） |
| 随机未注册标签（tiktokcdn-us.com 系） | NXDOMAIN（不返回污染正答案） |
| 国内视图 www.qq.com / www.baidu.com | NOERROR，正常国内地址 |
| AGH 上游 | 仍为唯一 guard，fallback_dns: []、bootstrap_dns: [] |
| 公网 53 | 无 UDP/TCP 53 监听 |
| 发布一致性 | RELEASE-CONSISTENCY OK，失败语义无回归 |

结论：本次入口调优只动 nginx 限流与上游连接方式，未触碰 DNSSEC / R8 / fail-closed / 国内分流配置，边界不变。

## 6. 已知边界与风险（如实登记）

1. limit_conn perip 32 仍是 DoH 瞬时并发的硬墙；是否放宽需单独决策。
2. DoT 入口没有速率限制（只有每源 32 并发 + 全端口 512 并发），长连接内可持续发查询。
3. AGH allowed_clients: []，公网匿名可用（审计 F3，按决策保留）。
4. upstream agh_doh 写死容器 IP 172.18.0.2，容器重建/换网段时须由对账脚本同步。
5. 单机故障域未变（审计 F5）。

## 7. 回滚

- nginx：删除 upstream agh_doh 块、rate 改回 50r/s、burst 改回 100、proxy_pass 改回 https://127.0.0.1:4443，
  然后 nginx -t && systemctl reload nginx。
- 只回滚限速：把 rate=200r/s 与 burst=200 恢复原值即可，upstream 可保留（不影响正确性）。

## 8. 复现要点

- 发压机与被测机分离；预热 3–5 s；每档重跑前清空输出目录（驱动脚本对输出目录用 mkdir(exist_ok=False)）。
- 语义失败（EXPECTED_POSITIVE / RRDATA_MISMATCH / EXPECTED_NODATA）与链路失败分开统计，否则会把上游抖动误读为接口不可用。
- 观察服务端心跳与 MemAvailable；1.8 GiB 主机在 800 q/s 时仍可运行，但余量有限。

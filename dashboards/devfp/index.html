看板口径与局限

只看用本机 DoT/DoH 的设备（服务器侧按指纹聚类）。数据来源三路：被动抓包（853/444/443 的 TLS ClientHello → JA3/JA4、TCP SYN → p0f 式指纹、握手 RTT）、AdGuard Home 查询日志（协议/查询行为）、nginx DoH 访问日志（HTTP 层指纹）。全部只读采集，不介入 DNS 解析链路。

设备卡片上的「推断」是用 TLS 栈结构 + TCP/IP 特征 + 查询域名 + HTTP 层 + 连接行为合成的结论，点开可看逐条证据。跨 NAT 看不到 MAC，因此无法对应到具体硬件型号；域名规则给出的厂商/OS 只是概率性线索，一律标注置信度并保留原始证据。证据不足就写「未识别」，不猜。

      登记会采集什么 · 有哪些局限
      

        
页面会采集浏览器全量特征（UA-CH 高熵项、GPU/WebGL、字体、Canvas/AudioContext、屏幕与时区、权限与编解码矩阵等），写入四个持久 ID（localStorage / IndexedDB / Cookie / Cache），并让这次 HTTPS 访问的 TLS 握手被抓包侧解析成 ja4；同时判定这台设备此刻是否走 DoT/DoH。只在浏览器里读取公开属性，不发到任何第三方，采集内容可在上面预览。

        
关联规则：后端只给「建议」，不做自动绑定；选好目标点「保存关联」后这条决定就被钉住，不会再被任何自动逻辑改动。Chrome 会对 TLS 扩展做随机化，同一台机的 ja4 每次可能不同，所以持久 ID 才是稳定锚点。

采集说明与局限

      
采集方式、数据归属规则与已知局限。只读旁路观测，不介入解析链路。

    

    

      

        
DoT :853
由 Nginx stream 前置终结 TLS（AGH 的 853 已挪到宿主回环 127.0.0.1:8854），再以 DoT 转发给 AGH；devfp 仅旁路抓包观察。所以除 ClientHello/ServerHello 与 TCP 指纹外，还能拿到：逐连接的查询名/qtype/报文大小、EDNS 特征（PADDING 字节数、DO 位、宣称的 UDP 缓冲、DNS COOKIE、ECS）、0x20 大小写随机化、每查询时延。

        
DoH :443 / :444
两条路径都由 nginx 终结 TLS 并反代到 AGH（容器 443 只发布在回环 127.0.0.1:4443），可记录 HTTP 层（UA、头、方法、状态、URL/POST 里解出的查询域名、TLS 套件/曲线/ALPN/session 复用）。

        
查询行为的归属
AGH querylog 只按出口 IP 归属；DoT 明文用同 (ip, sport) 连接精确归属，命中不了时若该 IP 只有一台设备则按 IP 归属，否则不归属（宁缺勿错）。另有 AGH 日志与抓包记录毫秒级「时间对齐」作为兜底（仅独占 IP 有效）。

        
查询行为
由 AGH querylog 增量读取（协议、qtype、上游、过滤命中、时延、ECS、Top 域名、最近查询）。

        
设备聚类
JA4/JA3 + TCP 指纹；无 TLS 时退化为「源 IP + TCP 指纹」。

        
OS 猜测
启发式 p0f-lite（TTL 跳数/窗口/MSS/WScale/选项顺序），置信度分高中低，仅供参考，原始值一律完整保留。

        
探测连接
只完成 TCP 三次握手、不发 ClientHello 就关闭的连接（常见于上游健康检查/端口探测）会被标记为「无载荷探测」，并按其 TCP 指纹并入同源同指纹的设备，不会单独虚增设备。

        
握手时延
SYN-ACK 发出 → 客户端下一个包到达的实测 RTT（毫秒）。注意不是 SYN→SYN-ACK（那只是本机处理耗时）。

        
设备推断
跨 NAT 看不到 MAC；DoH 的 HTTP 层与 DoT 明文能看到一部分载荷，但都读不到硬件型号（唯一例外：设备主动打开 /join 页时，Android Chrome 会经 Sec-CH-UA-Model 自报机型）。推断引擎用七类证据合成厂商/OS/TLS 栈/版本区间/设备角色：①TLS 栈结构；②TCP/IP 特征；③查询域名规则库；④HTTP 层；⑤连接行为；⑥版本线索；⑦DoT 明文画像。每条证据都在设备详情「推断依据」里列出，证据不足就写「未识别」。

        
/join 浏览器采集
在设备上打开 dns.example.com/join 时，页面会在浏览器内就地计算指纹并上报（无第三方脚本、无外链）：屏幕与时区、Canvas/WebGL 渲染器与 20 项 GPU 上限、已安装字体与字体度量、音频栈、数学库输出、JS 引擎与 CSS/Intl 特性位、编解码与 WebRTC/WebGPU/语音包能力、键盘布局、存储与权限状态、电量、帧率等数百项能力位；并写四条通道的随机持久 ID（localStorage / Cookie / IndexedDB / Cache）用于跨会话归并。结果落在设备行 enrollments.fp2（保存最新一次，约 5 KB）；每次访问另追加一条访问记录（时间、IP、JA4、UA、DoT/DoH 保护判定）。请求头中的 Cookie / Authorization 一律脱敏为字符数。

        
采集分层
fp2 里的键按「会不会随时间 / 网络 / 电量变化」归到四层，并随记录写进 _meta.cls：L1 身份（屏幕与时区、UA-CH、GPU 与 20 项 WebGL 上限、字体与字体度量、数学库、Canvas、声纹）——同一台机重复访问应一致，是跨会话归并的主键来源；L2 硬件（媒体设备计数、音频栈采样率、WebGPU 适配器、帧率、存储配额、滚动条、触摸点与色彩深度）——由设备决定但会随外设插拔浮动；L3 软件栈（JS 引擎位、CSS 特性、Intl、编解码、存储与权限、语音包、错误栈）——升级浏览器就会变；L4 运行时（时钟偏移、堆内存、网络类型、电量、RTC 候选、可见性）——每次访问都不同。归并 hash 只取 _meta.stab 里那 7 个稳定字段，L4 永远不参与判断「是不是同一台设备」。未登记的新键会落进 cls.un，不会被猜着塞进某一层。

        
局限
① 服务器无公网 IPv6，只能看到 IPv4 客户端；② 家庭设备经 CPE NAT 后同源 IP，只能靠指纹区分，无法对应到具体硬件型号（设备打开过 /join 页的除外）；③ DoH 只能看到请求元数据、DoT 明文只覆盖 DNS 层，都看不到「设备内哪个 App 在解析」；④ 域名规则给出的厂商/OS 是概率性线索；⑤ 服务器侧一律看不到 MAC，没有 OUI 厂商库可用；⑥ Nginx stream 终结后，AGH 面板里 DoT 的客户端维度会退化成前端一个 IP；⑦ devfp 重启前就建立、之后不再发 SYN/ClientHello 的长连接无法指纹化。

        
保留策略
连接明细保留 7 天、DoH 请求保留 14 天；最近查询环形缓存 4 万条；小时级聚合长期保留。
